# 사용 사례 검증 준비도: 8가지 고려 사항

사용 사례 후보가 **검증(PoC·파일럿 등)으로 나아갈 준비가 되었는지** 판단할 때 확인할 사항.

| 고려 사항 | 확인해야 할 사항 |
|---|---|
| **워크플로우의 명확성** | 평가할 수 있을 만큼 프로세스 단계를 충분히 이해하고 있다 |
| **이해관계자 참여** | 적절한 인력이 참여하고 있으며 기꺼이 협력할 의지가 있다 |
| **프로세스 성숙도** | 프로세스가 충분히 안정적이어서 현재 방식과 개선된 방식을 비교할 수 있다 |
| **정보 이용 가능성** | 필요한 입력 자료, 예시 또는 원본 자료를 적절하게 접근하고 검토할 수 있다 |
| **데이터 준비 상태** | 입력 자료가 이용 가능하며, 대표성을 갖추고, 검증을 위해 사용 권한이 부여되어 있다 |
| **위험 및 통제** | 오류는 되돌리거나 관리할 수 있으며, 사람의 검토나 승인이 현실적으로 가능하다 |
| **측정 명확성** | 일치하는 기준선과 합의된 수용 기준을 통해 개선 사항을 관찰할 수 있다 |
| **범위 및 복잡성** | 검증에 과도한 종속성, 전사적 재설계 또는 불분명한 책임 소재가 필요하지 않아야 한다 |

## 고려 사항별 관련 문서 (참고용 정리)
| 고려 사항 | 관련 문서 |
|---|---|
| 워크플로우의 명확성 | 10 (워크플로우 파악) |
| 이해관계자 참여 | 06 (이해관계자), 07 (고객의 헌신) |
| 프로세스 성숙도 | 10, 12 (AI 성숙도 신호 — 진행 중인 프로세스 변경) |
| 정보 이용 가능성 · 데이터 준비 상태 | 13 (데이터 민감도·사내 정책), 01 (샘플 데이터 확보) |
| 위험 및 통제 | 13 (인적 검토·승인), 15 (사람의 역할) |
| 측정 명확성 | 11 (기준값 검증, 사실 vs 가정) |
| 범위 및 복잡성 | 08 (첫 사례가 너무 광범위함 주의) |

## 컨설팅 적용
- 사용 사례 후보마다 8가지를 **충족 / 부분 / 미충족**으로 표시한다. 이것은 고객 평가가 아니라 **사용 사례의 검증 준비도** 점검이다.
- "미충족" 항목이 있으면 바로 검증에 들어가지 말고, 그 항목을 해소하는 것을 다음 단계로 정한다 (예: 샘플 데이터 사용 권한 확보, 기준 완료 시간 측정).
- 여러 후보 중 첫 사례를 고를 때 비교 기준으로 쓴다. 특히 **위험 및 통제**(오류를 되돌릴 수 있는가)와 **범위 및 복잡성**(한 팀·한 책임자로 끝나는가)이 좋은 첫 사례를 가르는 경우가 많다.
- **프로세스 성숙도**가 낮은 경우(프로세스가 매번 다르거나 개편 중) AI 효과를 비교할 수 없으므로, 프로세스 정리 자체를 먼저 제안하는 것이 나을 수 있다.
- **측정 명확성**: 검증 전에 기준선(현재 값)과 수용 기준(어느 정도면 성공인지)을 고객과 **합의**해 둔다.
