# 사용 사례 비교와 우선순위 정하기

> 출처: AX컨설팅팀 교육 자료 (2026-10-22 공유)
> 관련: `15_워크플로우_문제에서_사용_사례로.md`, `16_워크플로우_이해를_통한_기회_파악.md`, `17_사용_사례_검증_준비도.md`

## 목표
- **공식적인 점수표를 만들거나 수치 등급을 매기는 것이 아니다.**
- 간단한 비교를 통해 **체계적인 논의**를 이끌어내고, 파트너와 고객 모두가 **일관되게 옵션을 평가**할 수 있도록 돕는 것이다.

## 비교 요소 7가지

| 비교 요소 | 물어야 할 질문 |
|---|---|
| **비즈니스 가치** | 이것이 고객에게 어떤 개선을 가져다줄 수 있는가? |
| **워크플로우 준비 상태** | 워크플로우를 검증할 만큼 충분히 이해하고 있는가? |
| **데이터 준비 상태** | 필요한 입력 데이터가 확보되어 있고, 대표성을 갖추었으며, 접근 권한이 부여되어 있는가? |
| **위험 및 통제** | 어떤 문제가 발생할 수 있으며, 사람의 검토나 감독을 통해 이를 관리할 수 있는가? |
| **이해관계자의 지원** | 이 사용 사례에 관심을 갖는 주체는 누구이며, 그들이 참여할 의향이 있는가? |
| **측정 기준의 명확성** | 고객이 워크플로우가 개선되었는지 확인할 수 있는가? |
| **확장 가능성** | 이 사용 사례에서 얻은 증거가 향후 더 광범위한 도입을 뒷받침할 수 있는가? |

> 17 문서의 검증 준비도 항목과 대부분 겹치며, 여기서는 **비즈니스 가치**와 **확장 가능성**이 더해져 여러 후보를 **서로 비교**하는 데 초점이 있다. (참고용 정리)

## 비교표 양식 (참고용 정리)
점수 대신 **짧은 근거 문장**으로 채운다. 필요하면 강함 / 보통 / 약함 정도의 정성 표시만 덧붙인다.

| 비교 요소 | 후보 A: 온보딩 서류 필수 항목 추출 | 후보 B: 온보딩 진행 현황 모니터링 | 후보 C: ... |
|---|---|---|---|
| 비즈니스 가치 | 수동 검토 부담 감소 (코디네이터 체감 큼) | 지연 감소, 신입 경험 개선 | |
| 워크플로우 준비 상태 | 서류 검토 단계는 비교적 표준화됨 | 부서별 진행 방식이 제각각 | |
| 데이터 준비 상태 | 샘플 서류 확보 가능, 개인정보 포함 → 사용 권한 확인 필요 | 부서별 시스템 분산, 연동 여부 미확인 | |
| 위험 및 통제 | 추출 오류는 담당자 검토로 관리 가능 | 알림 누락 시 영향 작음 | |
| 이해관계자의 지원 | 인사 운영 책임자 관심 있음 | IT·시설 참여 필요, 의향 미확인 | |
| 측정 기준의 명확성 | 건당 검토 시간으로 측정 가능 (기준값 측정 필요) | 준비 완료까지 일수로 측정 가능 | |
| 확장 가능성 | 다른 서류 업무(계약·증빙)로 확장 가능 | 다른 부서 간 협업 업무로 확장 가능 | |

*(표의 후보 내용은 14·16 문서 온보딩 예시를 바탕으로 만든 가상의 예시)*

## 컨설팅 적용
- 사용 사례 후보가 2개 이상 나오면 이 비교표를 **고객과 함께** 채운다. 고객이 직접 근거를 말하게 하면 공통 이해(05)와 참여(07)를 동시에 얻는다.
- 숫자 점수를 합산해 자동으로 1위를 고르지 않는다. 비교표는 **논의 도구**이고, 최종 선택은 고객과 합의한다.
- 근거 칸이 "모름"이면 그것이 해당 후보의 **다음 확인 사항**이다 (11 문서: 가정은 질문으로 취급).
- 첫 사례는 보통 **가치가 분명하면서 위험이 관리 가능하고 빨리 증거가 나오는** 후보가 유리하다(17 문서). 확장 가능성이 높으면 이후 단계의 설득 근거가 된다.
