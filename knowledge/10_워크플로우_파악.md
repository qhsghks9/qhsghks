# 워크플로우 파악: 마찰 지점 찾기

> 출처: AX컨설팅팀 교육 자료 (2026-10-22 공유)
> 관련: `01_요청을_기회근거로_전환.md`, `05_문제에_대한_공통_이해.md`, `09_디스커버리의_진정한_의미.md`

## 목표
- 상세한 **프로세스 맵을 작성하거나 모든 활동을 문서화하는 것이 아니다.**
- 대신 다음을 파악할 수 있을 만큼 워크플로우에 대한 **충분한 이해**를 쌓는 것이다.
  - 문제가 **발생하는 지점**
  - **영향을 받는 대상**
  - 그 문제가 **왜 중요한지**

워크플로우 내에서 **마찰을 찾아낼 수 있게 되면**, 기회를 파악하고 추가 조사가 필요한지 여부를 판단하기가 훨씬 쉬워진다.

## 간단한 사고 방식 (다이어그램)

```
Input → Step 1 → Step 2 → Handoff → Review → Output
                      │
                      ▼
          Where is the work slowing down?
            (업무가 어디서 느려지는가?)
```

업무가 다음과 같아지는 지점을 찾는다.
- **느려지는** 지점
- **일관성이 떨어지는** 지점
- **비용이 많이 드는** 지점
- **위험한** 지점
- **완료하기 어려워지는** 지점

## 워크플로우를 파악하는 데 유용한 질문
마찰의 원인을 파악하는 가장 좋은 방법은 **업무가 실제로 어떻게 수행되는지 살펴보는 것**이다.

1. 현재 이 업무는 **어떻게 수행**되고 있습니까?
2. **무엇이 먼저** 일어나고, **그 다음에는** 어떤 일이 일어나나요?
3. **지연, 병목 현상 또는 비효율성**은 어디에서 발생하나요?
4. 어떤 단계에서 **가장 큰 마찰**이 발생하나요?
5. 업무는 **누구에게, 혹은 어떤 시스템으로** 전달되나요?
6. 마지막에는 **어떤 결과가 산출**됩니까?

> 위 질문은 다이어그램 흐름과 대응한다: 1·2 → Input~Step, 3·4 → 마찰 지점, 5 → Handoff, 6 → Output

## 단계별로 확인할 질문 (참고용 정리)

| 단계 | 확인 질문 예시 |
|---|---|
| Input (입력) | 업무는 무엇으로 시작되나요? 입력 자료의 형태·품질이 일정한가요? |
| Step 1, 2 (처리) | 각 단계를 누가 하고, 시간이 얼마나 걸리나요? 사람마다 결과가 다른가요? |
| Handoff (인계) | 다른 사람·팀·시스템으로 넘어갈 때 대기·누락·재작업이 생기나요? |
| Review (검토) | 누가 검토·승인하나요? 반려되거나 되돌아오는 일이 잦은가요? |
| Output (산출물) | 결과물은 누가 받고, 늦거나 틀리면 어떤 영향이 있나요? |

## 컨설팅 적용
- 화이트보드나 메모에 위 6단계 정도의 **간단한 흐름**만 그리고, 마찰 지점에 표시한다. 세부 프로세스 맵은 Stage 1 이후 공동 작업에서 다룬다.
- 마찰은 보통 **Handoff(인계)와 Review(검토)** 에서 많이 발생하므로 특히 자세히 묻는다.
- 마찰 유형(느림·비일관·고비용·위험·완료 어려움)을 05 문서의 영향 축(시간·비용·위험·속도·품질·CX)과 연결해 가치 스토리로 만든다.
- 마찰 지점을 직접 설명해 줄 사람은 06 문서의 **현업 실무자**다.
