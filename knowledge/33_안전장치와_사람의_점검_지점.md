# 안전 장치와 사람의 점검 지점

> 출처: AX컨설팅팀 교육 자료 (2026-11-04 공유)
> 관련: `13_거버넌스_및_운영_맥락.md`, `30_에이전트형_AI란.md` (인간의 통제), `31_에이전트가_아닌_것.md`, `32_목표_지침_맥락.md`

에이전트 기반 워크플로우에는 **명확한 경계**가 필요하다.

| 개념 | 설명 |
|---|---|
| **가드레일** | 에이전트가 **할 수 있는 일과 할 수 없는 일**을 정의하는 제약 조건이다. 이는 에이전트가 사용할 수 있는 **정보원**, 취할 수 있는 **조치**, 피해야 할 **콘텐츠**, 또는 워크플로가 **중단되어야 하는 시점**을 안내한다 |
| **인적 점검 지점** | 워크플로가 계속 진행되기 전에 **사람이 검토하거나 승인**하는 단계다 |
| **위험 민감도** | **위험도가 높은** 워크플로는 일반적으로 **더 강력한 감독**과 **명확한 에스컬레이션 절차**가 필요함을 의미한다 |
| **모니터링 및 피드백** | 조직이 **문제를 파악**하고 시간이 지남에 따라 **워크플로를 개선**할 수 있도록 돕는다 |

*(원문 번역의 "상담원"은 영어 "agent"의 오역으로 보여 "에이전트"로 표기)*

## 32 문서와의 관계 (참고용 정리)
- 32 문서의 **지침**(피해야 할 것, 중단·도움 요청 시점)과 **접근 경계**가 여기서 **가드레일**로 구체화된다.
- 32 문서 목표의 **"사람의 승인 지점"** 이 여기서 **인적 점검 지점**이다.

## 호텔 예시에 적용 (참고용 정리)
| 개념 | 적용 |
|---|---|
| 가드레일 | 회사 지정 예약 시스템만 사용 / 출장 규정 한도 초과 호텔 제외 / 결제 정보 직접 입력 금지 / 예산 내 후보 없으면 중단 |
| 인적 점검 지점 | 예약 확정·결제 전 출장자 승인 |
| 위험 민감도 | 낮음~중간(금액·취소 가능 여부) → 단일 승인으로 충분. 환불 불가 요금이면 추가 확인 |
| 모니터링 및 피드백 | 추천 대비 실제 선택률, 규정 위반 시도 건수, 사용자 수정 사항을 기록해 지침 개선 |

## 위험 민감도에 따른 통제 수준 (참고용 정리)
| 위험 수준 | 예시 업무 | 통제 |
|---|---|---|
| 낮음 | 내부 문서 요약, 초안 작성 | 결과 검토는 사용자 재량, 사후 모니터링 |
| 중간 | 고객 응답 초안, 티켓 분류·배정 | 발송·확정 전 인적 점검 지점, 예외 시 에스컬레이션 |
| 높음 | 결제·계약·규제 판단, 외부 시스템 변경, 개인정보 처리 | 단계별 승인, 강한 가드레일, 명확한 에스컬레이션 절차, 감사 로그, 27 문서 기준 전문가 검증 |

> 위험 수준을 가르는 핵심 질문: **실수를 되돌릴 수 있는가? 외부(고객·규제기관)에 영향이 가는가?** (25 문서: 사람의 역할과 되돌릴 수 있는 여부)

## 디스커버리·설계 시 확인 질문 (참고용 정리)
- 에이전트가 **절대 하면 안 되는 일**은 무엇인가? (가드레일)
- 어느 단계에서 **누가** 검토·승인하는가? (인적 점검 지점 — 15 문서 사람의 역할)
- 이 워크플로의 실수는 **되돌릴 수 있는가**, 영향은 얼마나 큰가? (위험 민감도)
- 예외 상황은 **누구에게 어떻게** 넘기는가? (에스컬레이션)
- 무엇을 **기록·관찰**해서 개선할 것인가? (모니터링 및 피드백 — 19 문서 성공 신호와 연결)

## 컨설팅 적용
- 에이전트 사용 사례 제안 시 위 4가지를 **반드시 함께** 명시한다. 31 문서처럼 "에이전트는 거버넌스를 대체할 수 없다."
- 가드레일·점검 지점의 **구체적 설계(권한 설정, 로깅 구조 등)** 는 27 문서 기준 판매자가 결정하지 않고, 기술·보안 담당과 검증한다. 판매자는 **필요성과 위치를 식별**한다.
- 모니터링 및 피드백은 도입 후의 개선 루프이자, 13 문서의 **가시성·모니터링·감독** 고려 사항과 같은 축이다.
