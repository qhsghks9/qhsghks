# 워크플로우 이해를 통한 기회 파악 (AI가 지원할 수 있는 업무 패턴)

> 출처: AX컨설팅팀 교육 자료 (2026-10-22 공유)
> 관련: `10_워크플로우_파악.md`, `15_워크플로우_문제에서_사용_사례로.md`

## 고객이 말하지 않은 기회까지 찾기
- 고객은 대개 자신이 느끼는 **불편함을 가장 직접적으로** 설명한다.
- 워크플로우를 **더 깊이 들여다보면** 고객이 아직 언급하지 않은 **추가적인 기회**를 발견할 수 있다.

## 워크플로우 검토 시 찾아볼 지점
사람들이 다음과 같은 상황을 겪는 지점을 찾는다.
- 행동을 취하기 전에 **여러 출처를 훑어보는** 경우
- 문서, 이메일, 대화록, 양식 또는 티켓에서 **정보를 복사하는** 경우
- 업무를 **분류, 정리, 우선순위 지정 또는 배정**해야 하는 경우
- 메시지, 요약, 계획, 보고서 또는 기타 산출물을 **초안으로 작성**하는 경우
- 업무의 품질, 완성도, 위험성 또는 준비 상태를 **검토**하는 경우
- **불완전하거나 산발적인 맥락** 속에서 의사결정을 내리는 경우
- 팀 간 **업무 인계를 조정**하거나 **진행 상황을 모니터링**하는 경우

> 이것들은 **제품 요구사항이 아니다.** 이는 **업무 패턴**이다.
> 이를 통해 AI가 프로세스 단계 중 **어디를 지원할 수 있는지** 파악하는 데 도움이 된다.

## AI 지원 유형 7가지
(워크플로우 단계에서 AI가 무엇을 해야 하는지 묻는) 질문에 대한 답은 종종 워크플로우에 필요한 **지원 유형**을 드러낸다.

| AI 지원 유형 | AI가 생성하거나 변경하는 것 | 예시 |
|---|---|---|
| **정보 검색** | 근거에 기반한 답변, 요약, 비교 또는 종합 | 승인된 출처 전반에서 관련 정책 지침 찾기 |
| **추출** | 비정형 입력 자료에서 구조화된 필드 또는 사실 추출 | 제출된 양식에서 필수 필드 추출 |
| **분류 또는 라우팅** | 라벨, 카테고리, 대기열, 우선순위 또는 라우팅 제안 | 이슈 유형별로 지원 티켓 분류 |
| **생성** | 초안, 메시지, 요약, 계획 또는 보고서 | 고객 응답 초안 작성 |
| **검토** | 조사 결과, 주의 사항, 품질 점검 또는 완성도 점검 | 요구되는 정보가 누락되었는지 요약 초안을 검토 |
| **권장 사항** | 제안된 다음 조치 또는 우선순위가 지정된 옵션 | 관리자가 검토해야 할 후속 조치를 권장 |
| **조정 또는 모니터링** | 상태 업데이트, 예외 사항 또는 알림 | 지연되거나 완료되지 않은 온보딩 작업을 표시 |

### 업무 패턴 ↔ AI 지원 유형 대응 (참고용 정리)

| 위의 업무 패턴 | AI 지원 유형 |
|---|---|
| 여러 출처를 훑어봄 | 정보 검색 |
| 정보를 복사함 | 추출 |
| 분류·정리·우선순위·배정 | 분류 또는 라우팅 |
| 초안 작성 | 생성 |
| 품질·완성도·위험·준비 상태 검토 | 검토 |
| 불완전한 맥락에서 의사결정 | 권장 사항 |
| 인계 조정·진행 모니터링 | 조정 또는 모니터링 |

> 대부분의 예시 문구에 **사람의 역할**이 남아 있다는 점에 주목: "승인된 출처", "초안", "관리자가 검토해야 할" 등. AI는 산출물을 만들거나 제안하고, 판단·승인은 사람이 한다.

## 예시 다이어그램: 하나의 문제 → 원인 → AI 지원 유형 → 결과

```
                 Employee onboarding is taking too long
                    (직원 온보딩이 너무 오래 걸린다)
                                   │
   ┌──────────────────┬────────────┴──────┬────────────────────┐
   ▼                  ▼                   ▼                    ▼
Multiple          Manual HR           Manager              Limited status
channels          validation          waiting time         visibility
(여러 채널)       (수동 HR 검증)       (관리자 대기 시간)    (제한된 현황 가시성)
   │                │      │              │                    │
   └───────┬────────┘      │              └─────────┬──────────┘
           ▼               ▼                        ▼
   Information        Knowledge               Workflow
   extraction         retrieval               monitoring
   (정보 추출)        (지식/정보 검색)         (워크플로우 모니터링)
           │               │                        │
           ▼               ▼                        ▼
   Reduce manual      Improve                 Reduce delays
   review effort      consistency             (지연 감소)
   (수동 검토 부담 감소) (일관성 향상)
```

| 원인 (워크플로우 마찰) | AI 지원 유형 | 희망하는 결과 |
|---|---|---|
| 여러 채널로 들어오는 정보 + 수동 HR 검증 | **정보 추출** | 수동 검토 부담 감소 |
| 수동 HR 검증 | **지식(정보) 검색** | 일관성 향상 |
| 관리자 대기 시간 + 제한된 현황 가시성 | **워크플로우 모니터링** (조정 또는 모니터링) | 지연 감소 |

### 이 다이어그램에서 배울 점 (참고용 정리)
- 고객이 말한 문제("온보딩이 너무 오래 걸린다")는 **증상**이다. 워크플로우를 보면 **4가지 원인**으로 분해된다.
- 하나의 문제에서 **여러 사용 사례**가 나오며, 각 사용 사례는 서로 다른 **AI 지원 유형**과 **결과**에 연결된다.
- 원인과 지원 유형은 1:1이 아니다. 여러 원인이 하나의 지원 유형으로 묶이기도 하고(채널+검증 → 추출), 하나의 원인이 여러 지원 유형으로 이어지기도 한다(수동 검증 → 추출, 검색).
- 결과는 "AI 도입" 같은 기능이 아니라 **업무 개선 언어**(부담 감소, 일관성 향상, 지연 감소)로 표현한다.
- 이렇게 분해하면 첫 사례를 고르기 쉬워진다: 원인의 크기·데이터 준비 상태·거버넌스(13 문서)를 비교해 우선순위를 정한다.

## 컨설팅 적용
- 고객의 문제 진술을 위 다이어그램처럼 **문제 → 원인 → AI 지원 유형 → 결과** 4단으로 분해해 그려 본다. 고객과 함께 그리면 공통 이해(05 문서)를 만드는 데도 유용하다.
- 10 문서의 흐름(Input → Step → Handoff → Review → Output)을 따라가며 각 단계에서 위 7가지 패턴이 보이는지 확인한다.
- 고객이 말한 불편함 하나에 머물지 말고, **같은 워크플로우 안의 인접 패턴**도 기회 후보로 기록한다.
- 고객과 대화할 때는 "AI 기능" 대신 **업무 패턴의 언어**로 묻는다: "이 단계에서 여러 시스템을 찾아보시나요?", "어디서 정보를 옮겨 적으시나요?"
- 사용 사례를 정의할 때 "AI가 무엇을 **생성하거나 변경**하는가?"를 위 7가지 유형 중 하나(또는 조합)로 명시한다. 유형이 정해지면 필요한 데이터·검토 방식·평가 기준을 구체화하기 쉬워진다.
- 찾은 패턴은 15 문서의 사용 사례 문장 틀로 옮겨, 사람의 검토 지점과 기대 개선을 함께 정의한다.
